# 《world.execute(me);》参考视频分镜脚本

分析对象：`media/reference.mp4`。本稿用于先确认原片内容，再按本项目的 TypeScript / Three.js / WebGL2 / GLSL / HTML 文字层方式复刻。本稿保留制作前的全片观察记录；现已完成全片程序实现；120 秒至片尾的切点校准见 [完成记录](completion-120-236.md)。前 120 秒的实现与精校见 [30–120 秒记录](continuation-30-120.md) 和 [14–30 秒记录](refinement-14-30.md)。

## 1. 观察依据与时间精度

- 视频：1920 × 1080，16:9，标称 30000/1001 fps（约 29.97 fps），时长 **236.402 秒**，只有视频流，没有音频流。
- 单独配乐：`media/soundtrack.m4a`，AAC、44.1 kHz、双声道，时长 **236.518 秒**。两者时长相差约 0.116 秒，不能仅据此认定起点和节拍完全同步。
- 查看方式：覆盖全片的连续抽帧，先每 2 秒总览，再每 1 秒查看，另取部分半秒位置的大图核对文字。本稿不是逐帧 EDL；表中边界是**约秒级的镜头区间**，短促故障帧、文字进出和切点仍需精校，初步误差可达约 1 秒。
- 文字：引号或代码格式中的英文是可见画面文字；无法辨清的部分明确标注，不依据歌曲歌词补写。原片拼写也应保留，例如画面的 `DIMENTION`、`Transmition Complete`。
- 声音：本次没有完成配乐听辨与节拍定位，因此不将歌词声部、鼓点、音效或 BPM 写成已确认事实。下面的“节奏”指画面变化节奏。参考片无音轨，不能断言按钮、警告、打字有独立音效。
- 运镜：本片基本是二维动态图形。本文的“推进、拉远、摇移”指观众看到的视觉效果，多数可由图层变换实现，并不代表原作者一定使用了真实三维摄影机。

## 2. 全片视觉规则

**构图。** 大量黑场或炭灰底，主体通常放在画面中央，四周留出很大的负空间；窄横条可以贯穿屏幕，图标与小字组成系统 UI。数学段及恢复段会突然放大到超出边界，形成局部特写。

**字体与信息层次。** 主体为细、窄的无衬线英文。字号分三个层级：中央主句、上下方较小的系统说明、巨大的背景关键词。标题中的 `world.` 小、`execute` 大、`(me);` 位于右下。文字常逐字出现、被遮罩裁切、发生残影、随着图形旋转，不是统一放在底部的字幕。

**颜色。** 黑、灰、白是主色；开机盾牌为浅绿，对象小人为粉色；数学段短暂出现青色；时间旅行和性别配置段出现蓝色；错误和 EXECUTION 用红色；故障边缘常出现青红错位，另有 RGB 三色分离。

**背景与质感。** 前半段常有低对比竖向条纹、细扫描纹和暗角。亮白场也并非完全纯白。片尾接近纯黑。复刻时须区分“干净底图”和故障覆盖层，避免整片都加高强度噪声。

**四类主要故障。** ①窄横带按不同距离错位；②青红/RGB 通道分离；③大块亮灰条带、棋盘状块和扫描撕裂；④多彩数字噪声及红色受损画面。原片片尾注明使用 Screen Glitch 与 Digital Glitch 影像素材，所以程序重建这些效果属于视觉近似，不应把它们理解为同一种随机抖动。

## 14. 对应当前项目的复刻方案（建议，不是原片事实）

1. **时间轴重新建立。** 用参考片的 0–236.402 秒作为主时间；不能沿用 `world.timeline.json` 的暂定 130 BPM、八个数学场景和 147.692 秒终点。先用本稿的章节建立大段，再把每条分镜拆成事件，逐帧校准进出点。
2. **保留确定性求值。** 沿用 `Timeline` / `SceneManager` / `SceneContext.time` / `localTime`；每次根据绝对时间重算图形、字数、进度和遮罩。加载、终端追加、随机故障都应能直接跳到任意时刻，避免累计状态。
3. **二维正交构图为主。** 以 1920×1080 设计坐标统一排版。大部分运镜变为 group 的 position / scale / rotation；只有斜平面、网格透视等需要额外透视处理。没有观察到的空间景别不要自行添加。
4. **增加实心图形层。** `Drawing` 可画轴线、曲线、圆环、心形和立方体；实心图标用 SVG 纹理、ShapeGeometry 或二维绘图纹理。不同姿态猫、垃圾桶盖等需要拆层或多状态图标。
5. **扩展文字层。** 当前 `Annotations.set` 只有位置、字号、颜色和透明度；需补充旋转、缩放、字距、遮罩、逐字显示和表格布局。若故障必须同时扭曲文字与图形，需要把文字合成到同一纹理/渲染目标，而不是让 HTML 始终浮在故障之上。
6. **故障用独立合成模块。** 建议分别控制扫描带位移、RGB 偏移、色块噪声、反相/闪色、整体暗化和残影。每次故障写明确的起止和强度；用固定种子及帧号求随机值，保证同一时刻完全相同。
7. **保留连续资产。** 电源—模拟立方体—系统 UI—几何心形—模拟立方体—电源构成全片呼应。共享图标几何和位置模板，比每场重新设计更容易还原。
8. **音画校准单独完成。** 先将单独配乐与原视频零点组合试听，再校准音频 offset、声部和强拍事件。不要未经听辨就把当前 BPM 套在分镜上，也不要擅自添加警告声/按钮声。
9. **先验三个代表片段。** 建议选 00:29–00:44（数学与文字变形）、01:47–02:08（系统 UI 与错误）、03:05–03:28（心形、线段重组与电源）。它们覆盖主要难点；确认风格和同步后再扩至整片。
10. **输出与比对。** 沿用按 `frame / fps` 渲染和 FFmpeg 导出的流程；对比应使用参考片的对应时间，而非只比较某个“相似场景”。原片是约 29.97 fps，若输出 60 fps需明确帧率变化，分镜时刻仍用秒保持一致。
